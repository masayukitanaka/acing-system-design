Craigslistのユーザーおよび投稿データのために、次のようなSQLスキーマを設計できます。

  • User: id PRIMARY KEY, first_name text, last_name text, signup_ts integer
  • Post: このテーブルは非正規化されており、投稿のすべての詳細を取得するためにJOINクエリは不要です。id PRIMARY KEY, created_at integer, poster_id integer, location_id integer, title text, description text, price integer, condition text, country_code char(2), state text, city text, street_number integer, street_name text, zip_code text, phone_number integer, email text
  • Images: id PRIMARY KEY, ts integer, post_id integer, image_address text
  • Report: id PRIMARY KEY, ts integer, post_id integer, user_id integer, abuse_type text, message text
  • 画像の格納： 画像はオブジェクトストアに格納できます。AWS S3やAzure Blob Storageは信頼性が高く、利用と保守が容易で、コスト効率にも優れているため人気があります。
  • image_address: オブジェクトストアから画像を取得するために使用される識別子。

ユーザークエリへの応答のように低レイテンシが求められる場合は、通常SQLや、低レイテンシのインメモリデータベース（例：Redis）を使用します。HDFSのような分散ファイルシステムを使うNoSQLデータベースは、大規模なデータ処理ジョブのためのものです。
